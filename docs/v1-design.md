# dw-mc v1: the decided design

`dw-mc` is a local CLI in TypeScript + Effect v4 that keeps the state of my open pull requests on disk, reads GitHub through `gh`, runs review runs through the local Claude Code, and shows me what every PR waits on. Nothing leaves the machine but those calls. It is built for me and installable by anyone.

Vocabulary is in [`CONTEXT.md`](../CONTEXT.md). Boundaries are in [`docs/adr/`](./adr/). This file is the rest: every decision the design interview settled, the mechanics that were verified by running them, and the order to build in. It is a snapshot; when a decision changes, this file changes.

## Decisions

| area                | decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| who orchestrates    | The tool. Facts, buckets, stamp and rebase are deterministic code. A model runs only inside a review run. A thin `/dw-mc` skill calls the CLI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| state               | JSON files validated with `Schema` on read, one directory of state outside any repo (`$XDG_STATE_HOME/dw-mc`, or `~/.local/state/dw-mc` when XDG says nothing). Review-run reports are Markdown next to them. SQLite only when a query the files cannot answer appears.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| git                 | Every run works in a worktree cut from the tool's own bare clone of the repo, kept in the state directory. My checkout is never touched. A review run's worktree is thrown away with the run; a fix session's is left standing, because the commits in it are mine. The fix worktree stands on `dw-mc/fix/<number>`, tracking the PR's branch so a plain `git push` lands on it: verified by running it, `git` refuses to fetch into a branch a worktree has checked out, and this clone fetches every branch on every run.                                                                                                                                                                    |
| GitHub, reads       | `gh` as me: `gh search prs --author=@me --repo <tracked>` for the sweep, `gh pr view --json` per PR, `gh api` for reviews, comments and check runs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| GitHub, writes      | Only pushes to branches I author, edits to my PR bodies (unused in v1), and re-runs of the failed jobs of a workflow run on a PR I author, plus the squash merge of a Ready, stamped PR I author ([ADR 0008](adr/0008-merging-my-own-pull-request.md)) and, where a repository turns it on, the review label on a PR I author ([ADR 0012](adr/0012-labelling-my-own-pull-request.md)). Never a comment, reply, thread resolve, review, approval or status. Comment-triggered reviewers a repo already has (CodeRabbit, a `@claude-review` workflow) are observed by author login and head SHA, never triggered.                                                                                |
| buckets             | Needs me › Needs review run › Waiting on others › Ready. A draft is a flag on a tracked PR, never acted on unless I ask.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Needs me            | Merge conflict, red CI that the flaky classifier calls legit, changes requested, a human comment newer than my last commit or comment, or a blocking finding on the current head.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Needs review run    | No review run recorded for the current head.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Waiting on others   | Nothing left for me, and a review from someone else is pending or CI is still running.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Ready               | Nothing is waiting: no review pending, no CI running. `dw-mc merge` lands it once it also carries my stamp (ADR 0008).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| review run          | Started by hand: `dw-mc review <pr> [--effort low\|medium\|high\|xhigh\|max]`. Runs in the foreground with progress; ends with a terminal bell and a macOS notification through `osascript`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| review turn         | A head carries one run, on Claude Code ([ADR 0009](adr/0009-one-review-run.md)). `review.command` with `review.effort` after it opens the run headless, and the findings come back on a second turn in the same session as schema-validated JSON. `review.prompt` is my own brief: beside a command it rides on `--append-system-prompt`, and without one it goes in front of the tool's own persona, which takes the schema inline and answers in a single turn. The persona body is derived from Addy Osmani's `code-reviewer` (MIT, recorded in `NOTICE.md`).                                                                                                                               |
| finding schema      | `{ verdict: clean \| findings, findings: [{ file, line, severity: error \| warning \| info, summary }] }`. Persona severities map Critical and Required to `error`, Optional to `warning`, Nit and FYI to `info`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| re-run rule         | A review run is repeated only when files outside the repo's `docs_only` globs changed since the last run on that PR.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| stamp               | Computed: a review run on the current head with no finding at or above `stamp.blocks_on`, CI green, mergeable. `dw-mc stamp <pr>` prints it and what it rests on; `dw-mc stamp --withdraw <pr>` removes it by hand until the head changes. The stamp is my bar, independent of the repo's own policy.                                                                                                                                                                                                                                                                                                                                                                                          |
| fixes               | Report only. `dw-mc fix <pr>` opens a MultiSelect of findings, takes an optional note per finding, then launches an interactive `claude` in a fresh worktree with the selected findings as JSON in the prompt. It refuses where the head moved since the run, so no session fixes a finding at a line that has gone. I steer and push. The session commits only where `fix.commits` or `--commit` says so; the tool itself never commits and never pushes. The re-review is a new review run. Inside an open session, `dw-mc findings <pr> --json` prints the same JSON, and `dw-mc fix <pr> --print` prints the whole prompt, picker and notes included, for a session I am already steering. |
| rebase              | Single branch only: when behind its base and CI is green or absent, rebase onto the base and `push --force-with-lease`. A conflict aborts the rebase, is written down with the files it hit and puts the PR in Needs me; a stop that `rerere` has a resolution for is carried past instead, so a conflict resolved once costs the next rebase nothing. Never while CI is running. A stacked PR is reported with its position; the stack is never driven.                                                                                                                                                                                                                                       |
| resolve             | `dw-mc resolve <pr>` opens a session on the conflict a rebase recorded at the current head: a worktree on `dw-mc/rebase/<pr>` that tracks the PR's branch and stands after the session, the rebase redone there and stopped on the conflict, and an interactive `claude` carrying the unmerged files and what the PR is for. `rebase.enabled` does not gate it, because it pushes nothing: finishing the rebase, committing and pushing are mine. `--print` prints the prompt and opens no session. `rerere` is on in the clone, so a resolution replays on the next rebase.                                                                                                                   |
| CI                  | Flaky versus legit by three deterministic signals: the default branch is red for the same workflow, the failing log names changed files, the log matches known flaky patterns. `dw-mc rerun <pr>` re-runs the failed jobs, once per head SHA, and refuses a head it has already re-run. A legit failure is reported, never fixed and never re-run.                                                                                                                                                                                                                                                                                                                                             |
| sweep               | On demand: `dw-mc sweep`, and implicitly when `dw-mc status` or the picker opens. No watch mode, no daemon, no discovery of new PRs in the background.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| interface           | Subcommands print tables, ruled between their columns. A run that takes minutes says so on one line it rewrites - spinner, what it reached for, how long - and falls back to a line per tool where there is no screen to measure. `dw-mc` with no arguments opens a picker built on Effect `Prompt`: pick a PR, pick an action, read the report. No full-screen TUI and no web UI in v1.                                                                                                                                                                                                                                                                                                       |
| tracking            | `dw-mc init` run inside a repo registers `owner/repo` (from `gh repo view`) and its per-repo settings. The first `init` on a machine also runs the machine setup: `gh auth status`, the defaults, the state directory. There is no separate `setup` command, and nothing is asked. `--effort` and `--base` settle the settings of the repo it ran in, or the global defaults when it ran outside one. A run writes the file only where it would decide something differently, and keeps no comments in it.                                                                                                                                                                                     |
| config              | `$XDG_CONFIG_HOME/dw-mc/config.yaml`, or `~/.config/dw-mc/config.yaml` when XDG says nothing, with `defaults` and `repos["owner/name"]`. A future in-repo `.dw-mission-control.yaml` uses the same schema and is read from the default branch, never from the PR branch. Precedence: global defaults, then the in-repo file, then the global per-repo section. v1 ships the global file only.                                                                                                                                                                                                                                                                                                  |
| review instructions | Stay in the repo's `AGENTS.md` / `CLAUDE.md`, which the built-in review reads. `review.prompt` carries whatever else this repository's review should look at.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| naming              | Repository `dominikwozniak/dw-mc`, binary and package `dw-mc`, skill `/dw-mc`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Config schema

```yaml
launcher:
  command: [claude]            # program + argument prefix that starts Claude Code
  fix_args: []                 # flags only a fix session gets
defaults:
  base: null                   # default branch from gh when null
  review:
    command: /code-review      # the slash command a run opens on; null for none
    effort: low                # low | medium | high | xhigh | max; null appends nothing
    prompt: null               # my own brief; in front of the persona, or beside the command
    model: null
    docs_only: ["**/*.md", "docs/**"]
  ci:
    ignore: []                 # check names that do not count towards green
    flaky_patterns: []
  fix:
    commits: false             # whether a fix session may commit; --commit overrides it
  rebase:
    enabled: false
  stamp:
    blocks_on: error
  labels:
    enabled: false             # the review label on my own PRs (ADR 0012)
    approved: "review: approved"
    changes: "review: changes"
repos:
  owner/name:
    # same keys, overriding defaults
```

## Verified mechanics

Each line says whether it was run or read.

- Run: `claude -p "/code-review low" --output-format stream-json --verbose` works headless; in print mode that output format refuses without `--verbose`. The findings come back as text in `result`, one `file:line — description` per line, beside the `session_id`. No `ReportFindings` tool call appears in the stream and `structured_output` is empty.
- Run: a detached worktree cut from the tool's own bare clone is enough for the built-in review: the clone carries `refs/heads/main`, so `git merge-base HEAD main` resolves there and the review diffs the pull request against the base branch as it would in my own checkout. Neither `git clone --bare` nor `gh repo clone -- --bare` writes a `remote.origin.fetch`, so that base branch only moves on where the fetch asks for it by refspec.
- Run: the report is every assistant turn's text, not the `result` alone. A repository whose own `/code-review` fans out to subagents ends on a remark about the notification that came back, and that remark is what `result` carries; the report is the turn before it.
- Run: passing `--json-schema` on that same call breaks it: `result` becomes `Command completed`.
- Run: `claude -p --resume <session_id> "Report the findings as structured output…" --output-format json --json-schema <schema>` returns the findings as validated JSON under `structured_output`, with line numbers more accurate than the text. The `session_id` comes from the first call's JSON result.
- Run: `claude -p "/security-review"` headless returns nothing: zero turns, empty result. Not a review command.
- Run: `claude -p "<a prompt of our own>" --output-format stream-json --verbose --json-schema '<inline JSON>'` gives both in one turn: the prose in the assistant turns and the validated findings in the result's `structured_output`. The flag takes inline JSON and not a path - a path is where it answers `--json-schema is not valid JSON`. This is why a run with no slash command is one turn where a run with one is two: the flag breaks only on the slash command.
- Run: a worktree of the tool's bare clone that stands on a branch the clone fetches makes the next `git fetch '+refs/heads/*:refs/heads/*'` exit 128 with `refusing to fetch into branch`, which is why a fix worktree stands on a branch of the tool's own. With `branch.<b>.merge` set to the PR's branch and `push.default upstream`, a plain `git push` from that worktree lands on the PR.
- Read, in the Claude Code docs: `claude --resume <id>` resolves a session across directories from 2.1.223, so a fix session can open in a worktree the review did not run in. Confirm by running it before relying on it.
- Read, in the plugin's command file: the `code-review` marketplace plugin posts a comment with `gh pr comment`. Read, in the Claude Code docs: the built-in `/code-review` comments only with `--comment`, which the tool never passes.

| tables                           | none in Effect; a small formatter of our own on `Terminal`                                                                                       |

## Patterns lifted from the references

The reference trees are vendored in the private workshop, the sibling directory `dw-mission-control`, under `repos/` with a router in `repos/AGENTS.md`.

- Quiet PR rule (skip a PR whose head SHA, CI conclusion and newest comment are unchanged): `haacked-dotfiles/ai/skills/babysit-prs/SKILL.md`.
- Flaky classifier signals and scoring: `haacked-dotfiles/ai/skills/ci-monitor/scripts/ci-classify-failure.sh`.
- Finding schema, fix prompt that carries the findings JSON verbatim, and separate reviewer and fixer sessions: `no-mistakes/internal/pipeline/steps/{common,review}.go`, `internal/types/findings.go`.
- Blocking reason as one function over mergeable state, review decision and check results: `talyn/packages/backend/src/services/githubGraphql.ts` `computeBlockingReason`.
- Re-run reviews only when non-doc files changed: `pauldambra-dotfiles/ai/skills/pr-shepherd/SKILL.md`.
- Reviewer persona for a run with no slash command: `addyosmani-agent-skills/agents/code-reviewer.md`.

## Build order

Each item is one tracer bullet: end to end, thin, observable.

1. `dw-mc init`: machine setup on first run, then repo registration from the current directory.
2. `dw-mc sweep` and `dw-mc status`: the read-only table with the four buckets.
3. `dw-mc review <pr> [--effort]` on the slash command; findings JSON and Markdown report on disk; `dw-mc findings <pr> --json`.
4. Computed stamp and `dw-mc stamp --withdraw <pr>`.
5. `dw-mc fix <pr>`: picker, notes, fix session in a worktree.
6. `dw-mc rebase <pr>` for a single branch, and the flaky re-run.
7. The tool's own prompt with the persona body, for a repository that configures no slash command.
8. The `/dw-mc` skill and the no-argument picker.
9. `dw-mc merge <pr>` behind the Ready-and-stamped threshold, in the picker behind a confirmation.

## Out of scope for v1

Summaries and repository graphs, PR body edits, driving stacks, automatic fixes of findings or CI, a watch mode or background discovery, a web UI, a full-screen TUI, a headless security review, and posting anything to GitHub beyond ADR 0002, ADR 0008 and ADR 0012.
